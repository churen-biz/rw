## 为什么要「双轨」而不是「先数学后 CS」 {#why-dual-track}

长期自学常见两种极端：

**极端 A：先三年数学再 CS**——证明能力很强，但写不出可靠系统，对「计算」缺乏肌肉记忆，读 Sipser 也缺工程直觉。

**极端 B：先三年工程再补数学**——能 shipped 产品，但看到定理就躲，算法分析停渐近，类型论与形式化永远「以后再说」。

地图要求的是**双轨并行**：数学轨培养定义、证明、结构、抽象；CS 轨培养实现、实验、系统、复杂度。两轨不是简单相加，而是**互相提供动机与印证**：

- 学期望分析时，hash table 的负载因子有了量；
- 学等价关系时，数据库范式与 partition 有了例子；
- 学 ε-δ 时，数值误差与浮点行为有了严肃语言；
- 写并发 bug 时，「直觉上的连续」与状态机不变式形成对照。

双轨节拍解决的是**操作问题**：在一周有限小时里，如何安排两轨、减少上下文切换税、何时交叉回顾、如何避免一轨饿死另一轨。

## 双轨的基本单元：块（Block）而非碎片 {#blocks}

系列第四篇建议 **90 分钟深度块**。双轨规则：

1. **同一天内最多切换轨道 1 次**（数学 ↔ CS），理想是**分日**；
2. 每块内不混：证明块不写代码，lab 块不翻 Hammack；
3. **回顾块**可以两轨合并：Redo 数学 + 写 lab 日志。

错误示范：每晚 30min 数学 + 30min CS + 30min 视频，一周七天——切换税爆炸，两轨都浅。

## 标准周模板 A：学生 18h {#template-student}

| 日 | 上午/下午块 1 | 晚上块 2 | 轨 |
| --- | --- | --- | --- |
| 周一 | 证明 90min | CS 阅读 60min | 数 / CS |
| 周二 | CS lab 120min | — | CS |
| 周三 | 证明 90min | 算法实现 90min | 数 / CS |
| 周四 | 学校课/作业 | 学校作业算「做」 | 混合 |
| 周五 | 回顾 Redo 90min | 掌握证据 30min | 双轨回顾 |
| 周六 | CS 项目 3h | | CS |
| 周日 | 数学习题 2h | 白纸/延迟测试 1h | 数 |

**比例粗算**：数学 ~8h，CS ~8h，回顾 ~2h。符合 20/60/20 且双轨均衡。

## 标准周模板 B：在职 10h {#template-employed}

| 日 | 块 | 轨 |
| --- | --- | --- |
| 周二晚 | Hammack 1 节 + 2 题 90min | 数 |
| 周四晚 | CSAPP 阅读 + lab 90min | CS |
| 周六上午 | 数学习题 2h | 数 |
| 周六下午 | 数据结构/C 项目 2h | CS |
| 周日 | Redo + 掌握证据 1h | 回顾 |

**策略**：一次只并行 **1 数学书 + 1 CS 线**；第三本书暂停。

## 标准周模板 C：考试季收缩 {#template-exam}

考试前 2 周：

- 数学轨：学校考试范围 + Redo，**不开新章**；
- CS 轨：维持**最小项目**（每周 2h，防手感丢）；
- 回顾：白纸旧章。

考后第一周：**不报复性开新书**，先 Redo 考前堆积的 R。

## 数学重周 vs CS 重周（交替） {#alternating}

若无法每日双轨，采用**双周节律**：

- **奇数周数学重**：数学 12h，CS 6h；
- **偶数周 CS 重**：CS 12h，数学 6h（维持 Redo，不推进新节）。

一个月内两轨总小时仍均衡，但单日专注更深。适合深度证明周（Abbott 极限章）与 lab 冲刺周（malloc）交替。

## 交叉回顾：周末 1 小时 {#cross-review}

每周日（或周五）留 **60 分钟交叉回顾**，回答三个问题：

1. **本周数学概念，能否在 CS 里找到一个实例？**  
   例：学了等价关系 → 查 partition 与 Union-Find 的连通分量。

2. **本周 CS 实现，依赖哪条数学定理或定义？**  
   例：hash 均摊 → 期望线性探测长度；并发 hash → 需重新理解不变式。

3. **哪一轨本周「假推进」？**  
   只读不做题 / 只写代码不记日志 → 下周纠偏。

写 5～10 行交叉回顾日志，存入活文档（系列第十篇）。

## 并行读同一主题的两面 {#same-theme}

某些周可**故意对齐主题**，放大交叉：

| 数学侧 | CS 侧 | 交叉点 |
| --- | --- | --- |
| MCS 图论 | BFS/DFS 实现 | 复杂度、正确性 |
| 概率期望 | 随机算法 lab | 指示变量法 |
| Abbott 连续 | 浮点误差实验 | ε 直觉 |
| 逻辑命题 | SAT solver 玩具 | 可满足性 |
| 群论（后期） | 对称加密数学 | 循环群 |

对齐不是必须，但对**第三年汇合**（逻辑+Sipser+类型论）极有帮助。

## 上下文切换与启动摩擦 {#context-switch}

从证明切换到代码，大脑需要 **10～15 分钟启动**。技巧：

- 块开始前 **2 分钟仪式**：证明块泡咖啡+摊纸；CS 块开 IDE+关通知；
- 块结束 **3 分钟收尾**：证明块写「卡在哪」；CS 块 `git commit` 或记 TODO；
- **不在块中间查社交软件**——切换成本远大于休息。

若只能 30 分钟碎片时间：**只做 Anki/Redo/读定义**，不要开新证明或新 lab。

## 双轨与四柱的对应 {#four-pillars-map}

| 轨 | 柱 |
| --- | --- |
| 数学轨主 | 证明离散、线代、分析、（后年）代数拓扑逻辑 |
| CS 轨主 | 算法、系统、（后年）网络数据库编译分布式 |
| 双轨交汇 | 算法正确性、复杂度、信息论、PL 类型 |

第一年双轨焦点：**Hammack/MCS + Axler + DS/C + CSAPP**。

## 能量管理：避免一轨永久饿死 {#starvation}

症状：

- 三个月未做数学题 → 证明手感退化；
- 三个月未写代码 → 指针与调试生疏。

**防饿死规则**：

- 再忙的 CS 重周，数学轨至少 **2h Redo**；
- 再忙的数学重周，CS 轨至少 **2h 维护项目**；
- 每月检查：两轨是否都有掌握证据更新。

## 与伙伴共学双轨 {#study-partner}

若有效学习伙伴：

- **数学日**：各自证明，交叉批改；
- **CS 日**：pair programming lab；
- **回顾日**：一人口试另一人（练 Level 5）。

无伙伴时，AI 口试 + 公开学习日志（可选）替代。

## 双轨节拍故障排查 {#troubleshooting}

| 症状 | 可能原因 | 调整 |
| --- | --- | --- |
| 两轨都焦虑 | 四开新书 | 砍到 1+1 |
| 数学永远推进慢 | 阅读占比过高 | 60% 做题 |
| CS 永远推进慢 | 无项目里程碑 | 定 v0.1 日期 |
| 周末报复性学习 | 平日零块 | 平日每晚 45min 保底 |
| 交叉回顾空白 | 未强制写日志 | 模板贴日历 |

## 季度双轨审计 {#quarter-audit}

每季度末填：

## 行动清单 {#action}

1. 选择模板 A/B/C 之一，写入日历；
2. 标定本周「数学日」与「CS 日」；
3. 预约周日 1h 交叉回顾；
4. 写第一条交叉回顾（哪怕只有 3 行）。

## 结语 {#closing}

双轨不是负担翻倍，而是**两只脚走路**。单脚跳可以快几步，但地图是六年。用块结构保护深度，用交替与交叉回顾保护两轨都不饿死——你会感到数学与 CS 越来越像同一门语言的不同方言。
