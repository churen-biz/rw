## 这不是一份课表，而是一张活地图 {#not-a-syllabus}

我想用 4～6 年（甚至更久）建立一张「现代数学 + 现代 CS」的知识地图。目标不是把 MOOC 和教材清单打勾，而是能真正回答这些问题：

- 什么是证明？什么是结构？什么是空间？
- 什么是计算？什么可以计算、什么不能、什么可以高效计算？
- 程序从源码到 CPU 执行，中间到底发生了什么？

这份路线有一个核心原则：**基础阶段追求广度，研究阶段追求深度。** 数学走「定义 → 例子/反例 → 证明 → 迁移」；CS 走「理论 → 实现 → 实验 → 重新理解理论」。节奏比速度重要——前 2～3 年先把地图铺开，之后再选一两个方向往地下挖。

> [!NOTE]
> 本文依据《现代数学 × 现代计算机科学：长期自学路线蓝图》整理，侧重**学习节奏与执行方法**。完整书单与章节级推荐请保留在原蓝图文档中，学完一门课后回头更新它。
>
> **展开阅读**：下文十个部分均已写成详细指导文档（每篇不少于五千字），见 [自学节奏指南系列](/docs/learning-rhythm/)。

## 先建立世界观，再谈进度 {#worldview}

> 详细指导：[01 世界观与学习目标](/docs/learning-rhythm/01-worldview/)

在正式排课之前，有一个心智模型值得先种下：

**数学对象 = 集合 + 额外结构。**

集合论像机器码——几乎所有经典数学对象都能被编码成集合。但数学家真正关心的不是「它本质上是不是集合」，而是**结构和保持结构的映射**：同构、线性同构、拓扑同胚，说的都是同一件事——重要的往往不是对象是什么，而是它们具有什么关系。

现代 CS 恰好站在交叉点上：数学研究结构，逻辑研究推理，CS 研究计算，概率研究不确定性，信息论研究信息。带着这张鸟瞰图去学，就不会在某个章节里迷路太久。

## 四根柱子：现在最该启动的组合 {#four-pillars}

> 详细指导：[02 四根柱子](/docs/learning-rhythm/02-four-pillars/)

不要一次开 20 本书。如果以今天为起点，先立四根柱子：

| 柱子 | 内容 | 推荐起点 |
| --- | --- | --- |
| 证明与离散 | 逻辑语言、集合、关系、图、计数 | Hammack *Book of Proof* → MIT *Mathematics for Computer Science* |
| 连续数学 | 线代 + 微积分/分析 | Axler *Linear Algebra Done Right*；学校高数先用，再用 Abbott 重建严格基础 |
| 算法与理论 | 数据结构、算法设计、计算理论 | Kleinberg & Tardos → CLRS；Sipser *Introduction to the Theory of Computation* |
| 计算机系统 | 从 C 到机器、OS、网络、数据库 | Bryant & O'Hallaron *CSAPP* |

认知升级的递进顺序是：**计算 → 证明 → 结构 → 映射 → 抽象 → 基础。** 范畴论、类型论、HoTT 很迷人，但不是现在的优先级——先见过「集合→函数、向量空间→线性映射、群→群同态」，再学 functor 和 natural transformation，才知道它在抽象什么。

> [!IMPORTANT]
> 范畴论、集合论（ZFC）、HoTT 都不要过早进入。见过大量数学结构之后回头学，收获会完全不同。

## 五年参考节奏：并行，而非串行 {#five-year-rhythm}

> 详细指导：[03 五年参考节拍](/docs/learning-rhythm/03-five-year-rhythm/)

不要把学年当成硬性先修表。下面是一张**参考节拍**，各条主线应尽量并行推进：

| 阶段 | 数学侧重 | CS 侧重 |
| --- | --- | --- |
| 第 1 年 | 证明、微积分、线代、离散数学 | Python/C、数据结构、CSAPP 入门 |
| 第 2 年 | 数学分析、概率、抽象代数 | 算法、体系结构、操作系统 |
| 第 3 年 | 拓扑、数理逻辑 | 计算理论、网络、数据库、编译 |
| 第 4 年 | 集合论、范畴论 | 编程语言、分布式系统、复杂性理论 |
| 第 5 年+ | 类型论 / HoTT / 专业方向 | ML / Crypto / PL / Systems / Theory 深入 |

数学主线的逻辑关系大致是：

```text
逻辑与证明 → 集合/函数 → 线性代数 → 数学分析 → 抽象代数 → 拓扑
                                      ↓
                         集合论/数理逻辑 → 范畴论 → 类型论/HoTT
```

但大学阶段（以及自学阶段）**不应完全串行**。例如：第一年就可以让 Hammack、Axler、MCS 和 CSAPP 同时推进——它们互相提供动机。学向量空间时，离散数学里的图论已经在练组合思维；写 CSAPP 的 lab 时，分析课里的 ε-δ 语言会在别处悄悄发芽。

## 每周怎么分配时间 {#weekly-allocation}

> 详细指导：[04 每周时间分配](/docs/learning-rhythm/04-weekly-allocation/)

经验比例：**20% 阅读 + 60% 做题/证明 + 20% 回顾整理。**

不必机械执行，但有一个硬规则——**一本数学教材不做习题，基本等于没有真正学。** 如果一周 10 小时，大致可以是：

- 2 小时读新内容（慢读，遇到定义就停下来拆成逻辑语言）
- 6 小时做题、写证明、写代码 lab
- 2 小时回顾：白纸测试、重做标记题、整理「我现在能做什么」

CS 侧的时间结构不同，但 spirit 一样：**读原理的时间应明显少于动手实现和调试的时间。**

## 三道护栏：防止「看懂了」的幻觉 {#three-guardrails}

> 详细指导：[05 三道护栏](/docs/learning-rhythm/05-three-guardrails/)

### 1. 30 分钟规则

重要证明题不要想 3 分钟就翻答案。至少认真攻击 20～30 分钟，写下：

- 已知什么？要证什么？
- 定义拆开是什么？
- 有没有简单例子？能否反证、构造或归纳？
- 能调用哪些已有定理？

实在卡住，先看提示再继续；完整解答是最后手段。

### 2. Redo 机制

看过解答的题标记 `R`。2～3 天后**完全不看答案**重新证明；仍不会标 `R2`，一周后再做，直到能独立完成。短期能复现 ≠ 长期掌握。

### 3. 每章白纸测试

合上书，在空白纸上写章节名，自己重建知识树。每个概念写四行：

```text
Definition → Example → Counterexample → Important Theorem
```

这比记录「今天读了 30 页」更能暴露漏洞。两周后再做一次**延迟测试**——不复习直接考自己，结果更可靠。

## 六级掌握模型：怎样判断真的学会了 {#six-levels}

> 详细指导：[06 六级掌握模型](/docs/learning-rhythm/06-six-level-mastery/)

「看懂了」不等于「学会了」。每个重要概念，用这张表自检：

| Level | 自测 | 含义 |
| --- | --- | --- |
| 1 定义 | 合上书能准确写出定义吗？ | 认识 |
| 2 例子/反例 | 能举 3 个例子、2 个反例，并指出违反哪条公理吗？ | 理解边界 |
| 3 基础证明 | 能从定义独立证明基本性质吗？ | 基本掌握 |
| 4 重新发现 | 面对新定理能先猜为什么成立并尝试证明吗？ | 主动理解 |
| 5 解释 | 能用直觉语言讲给别人，再切回严格定义吗？ | 深度理解 |
| 6 迁移 | 能把概念用于没见过的新对象/新问题吗？ | 真正掌握 |

Level 1～2 = 认识；1～4 = 基本掌握；1～6 = 真正理解。

举个例子：学完向量空间，不应只会处理 $\mathbb{R}^n$，还应能处理多项式空间、函数空间；学完群，既能举群，也能举「差一点但不是群」的反例，并指出缺的是哪条公理。

改变学习记录方式——不要写「这个月读完两章」，而写「我现在能做什么」：

```text
Linear Algebra — Vector Spaces
✓ 能定义 vector space
✓ 能判断 subset 是否是 subspace
✓ 能构造例子/反例
✓ 能证明 intersection of subspaces is a subspace
△ linear independence 的部分证明还不熟
✗ basis extension 仍需要提示
```

## CS 必须做东西 {#cs-projects}

> 详细指导：[07 CS 项目](/docs/learning-rhythm/07-cs-projects/)

数学的学习闭环是：**读定义 → 做题 → 写证明。**

CS 的学习闭环是：**读原理 → 实现 → 实验 → 发现问题 → 回到理论。**

只读 CSAPP 不做 lab，只学算法不写代码，地图永远缺一块。建议按阶段穿插小项目：

| 阶段 | 项目方向 |
| --- | --- |
| 第 1 年 | 手写 hash table、基础数据结构 |
| 第 2 年 | 算法题 + OS 相关小实验 |
| 第 3 年 | tiny language 编译器、HTTP server、mini database |
| 第 4 年+ | xv6、Raft、λ-calculus interpreter + type checker、Lean 形式化证明 |

项目不必大而全。一个能跑通、能讲清楚设计取舍的小东西，胜过十个半成品。

## 数学与 CS 的「双轨节拍」{#dual-track}

> 详细指导：[08 双轨节拍](/docs/learning-rhythm/08-dual-track/)

可以把每周学习想象成两条轨道，共享一个节拍器：

```text
数学轨：  读一小节 → 做习题 → 白纸测试 → Redo 错题
CS 轨：   读一小节 → 写代码/lab → 调试 → 回头用理论解释 bug
         ↓                              ↓
         └──────── 周末 1 小时交叉回顾 ──┘
```

交叉回顾时问自己：这周学的证明方法，能不能用在算法正确性上？这周写的并发 bug，和分析课里的极限/连续性直觉有没有隐约的相似？

概率论、信息论是横穿全局的副线——大二/大三再系统加入即可，但第一年就可以在日常中保持对「不确定性」的敏感：随机算法的期望分析、哈希冲突、网络丢包，都是入口。

## 节奏上的三个常见误区 {#pitfalls}

> 详细指导：[09 常见误区](/docs/learning-rhythm/09-common-pitfalls/)

**误区一：按书序串行，一本读完再开下一本。**
数学各分支互相提供动机。分析需要线代的语言，拓扑需要抽代的同构思想，离散数学需要证明课的基础。并行推进，允许某些章节先跳过、后回补。

**误区二：追求「读完」而非「能做什么」。**
一本书读三遍不如一个章节达到 Level 4。用掌握证据（能证明什么、能解释什么、能迁移到哪里）代替页数进度。

**误区三：只学理论或只写代码。**
纯数学不做题会停留在 Level 1；纯工程不读原理会在系统设计面前撞墙。四根柱子缺一不可，节奏上保持「证明与实现」的周交替。

## 活文档：每学完一门课更新什么 {#living-document}

> 详细指导：[10 活文档](/docs/learning-rhythm/10-living-document/)

这份路线图应是活文档。每学完一门课，不只打勾，而是更新：

1. **掌握证据**——按六级模型写「我现在能做什么」
2. **薄弱点**——标 `△` 和 `✗`，安排 Redo 和延迟测试
3. **项目记录**——做了什么、踩了什么坑、对应哪章理论
4. **下一阶段先修**——根据薄弱点调整并行顺序，而非机械跳下一年

可以用 AI 做口试辅助。学完一章后：

> 我刚学完《书名》第 X 章。不要直接给我答案。请像大学数学教授一样对我进行口试，从定义开始逐渐提高难度，一次只问一个问题，根据我的回答追问。如果我错了，先通过追问让我发现错误。最后按「定义、例子/反例、证明、解释、迁移」评价我的掌握程度和知识漏洞。

## 结语：慢，但是稳 {#closing}

四年六载听起来很长。但我们要建立的不是一张考试大纲，而是一套能持续 20 年的思维框架。前 2～3 年铺地图的阶段，最忌讳的是焦虑地横向比较「别人已经学到范畴论了」——**不需要成为所有领域的专家。**

先立四根柱子，用 20/60/20 的时间比例守住做题主线，用六级模型和 Redo 机制对抗「看懂了」的幻觉，用项目把 CS 理论钉进肌肉记忆。地图会一年比一年清晰；等到回头学集合论、范畴论和 HoTT 时，你会惊讶地发现——它们不是在添乱，而是在给已经走过的路一个统一的名字。
